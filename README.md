# Ambition Skill：高度 · 深度 · 广度

[English](README-en.md) | 简体中文

将模糊的“做得更好”转成有目标、有方法、有验证依据的任务。适用于方案审视、研究、产品规划及交付物改进。

## 来源

方法论来源于 **Felix Rieseberg** 的文章 [How to be more ambitious: A tutorial for humans with models](https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/)，原文发布日期为 **2026 年 10 月 13 日**。

这是基于文章的中文工作流改编，并非作者发布的官方 skill，也不是逐字翻译。完整论证与原文案例请阅读文章。

## 原文方法论与本 skill 的范围

| 维度 | 含义 | 本 skill 的处理 |
|---|---|---|
| Speed：速度 | 用更少时间完成同样的工作 | 作为背景说明，不单独展开 |
| Altitude：高度 | 从单项任务追溯最终结果 | 检查目标，并提出更高层次的交付 |
| Depth：深度 | 深入原始材料、专业工具和实际问题 | 检验假设，并指定独立验证依据 |
| Range：广度 | 引入其他领域的方法与技术 | 明确各领域实际贡献的动作和工具 |

原文列出四类，认为速度这一类已较成熟，因此重点讨论后三类。本 skill 沿用这个范围；这不意味着速度不重要或无需方法。

## 本仓库如何把方法变成工作流

以下六步、级别数量和输出模板是本 skill 的结构化整理，不是原文规定的统一流程：

1. **复述任务**：确认正在审视什么。
2. **选择维度**：选适用的 1–3 个维度，说明原因。
3. **提出阶梯**：每个维度给出 2–3 级方案及可直接使用的提示词。
4. **列出条件**：明确数据、工具、权限和环境缺口。
5. **指定外部裁判**：用测试、独立核算、留出集或实测结果判定成败。
6. **推荐路线**：选择一个能开始、能验证的级别。

“外部裁判”应与结论匹配。例如，程序测试可检查实现逻辑；涉及真实设备的预测，还需要独立工况或现场数据。这个区分是本仓库的应用说明。

评审与实施分开：未授权的执行先确认；已授权的任务沿推荐路线推进。数据不足时明确标注探索范围。

## 使用示例

以下提示词为本仓库的使用示例，并非原文引语。

**审视已有方案**

> 使用 ambition 审视这个方案。区分已实现能力、证据缺口和探索方向；给出升级阶梯、前置条件和外部验收依据。

**把任务做深**

> 使用 ambition 的 Depth 审视这份分析：指出需要回到哪些原始数据，哪些假设应该被挑战，以及怎样用独立数据验证结论。

**引入跨领域方法**

> 使用 ambition 的 Range 审视这个产品。为每个有帮助的领域指定实际动作、工具、输出和验收方式，最后推荐最值得先试的一组方法。
